🪜 2. REST o Eventos

Interacción REST Evento ¿Por qué?
Pedidos e Inventarios X Es una consulta síncrona; el cliente necesita confirmar existencia física antes de comprometer el pago.
Autenticación y Usuario X Requiere un "Handshake" inmediato para validar la sesión y permitir la navegación segura del usuario.
Pedidos y Notificaciones X Es comunicación reactiva (Fire-and-forget). El sistema de pedidos no debe esperar a que se envíe un SMS para continuar.

🪜 3. Síncrono o Asíncrono

Interacción Síncrono Asíncrono Justificación Técnica
Pedidos -> Inventario X Para garantizar la consistencia de datos (evitar sobreventa), el hilo de ejecución debe esperar la respuesta del stock.
Autenticación -> Usuario X La experiencia de usuario depende de una respuesta inmediata para autorizar el acceso a la plataforma.
Pedidos -> Notificaciones X Permite desacoplar los servicios. Si el servicio de notificaciones tiene alta latencia, no afecta la creación del pedido.

🪜 4. Eventos Importantes del Sistema

1️⃣ OrderCreated: Gatilla la reserva de productos y el cálculo de ruta logística.

2️⃣ PaymentProcessed: Evento que define si la orden avanza a preparación o se descarta.

3️⃣ StatusChanged: Notifica cambios de estado en tiempo real (Picking, En camino, Arribado).

💡 Glosario de Soporte
REST: Protocolo basado en HTTP para peticiones directas.
Evento: Mensaje que indica un cambio de estado en el sistema.
Síncrono: Flujo bloqueante que espera respuesta.
Asíncrono: Flujo no bloqueante basado en colas de mensajes.
Service Discovery: Mecanismo de detección automática de nodos de red.
